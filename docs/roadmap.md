# 路线图

里程碑按能力划分。本仓库当前提交的是 M0 脚手架：契约和示例可以校验，同时为后面的里程碑留了可运行的空壳。空壳不等于该里程碑已经完成。

## M0 契约

定下契约格式和对象，包括 Action 和 EvalCase。JSON Schema 为校验真源，YAML 为编写格式。内核能加载、校验、diff 和应用补丁。示例 Namespace（假期）用来证明这条链路是通的。

## M1 MCP 读工具与评测骨架

已经落地的部分：

- Rule 带生效日、废止日和替代指针。`query_rule_version` 按规则、主体和业务发生时点返回现行或已废止。
- `get_leave_days` 与 `get_limit` 按契约计算时长和限额，回执里带出处、基准、区间和结论。模型不心算。
- `retrieve_evidence` 可以同时返回现行文和已废止文，并标明查询时点是否现行。
- 口径对照 `eval_hr_001` 与版本干扰 `eval_exp_001` 可以入库。发布门禁检查口径、版本、证据引用和回执。
- 默认 MCP 运行时只注册读工具。`approve_leave`、`submit_expense`、`ingest_eval_case` 只在显式打开写脚手架时出现，而且仍然不写系统。
- `packages/harness` 把 `@deepseek-ai/dsh@0.2.2-rc.5` 包在自己的提议接口后面。补丁由内核校验。人确认发布不在 dsh 里。

故意还没做：调用火山方舟、真正执行写回、工作台问答界面，以及把 M0 合并进 main。

## M2 Harness 推导动作并生成评测用例

harness 按 `docs/harness-flow.md` 工作：读材料、提问、推导对象和 Action，证据不够就写 GapLog 并回到业务侧，最后生成 EvalCase。本里程碑尚未开始。

## M3 合并前回归与工作台评测视图

拉取请求上的回归成为正式门禁，工作台的评测页展示用例结果。M0 的 CI 已经调用占位评测，工作台评测页仍是说明文字。

## M4 编译到已有引擎

把指标编译到已有引擎，导出 OSI，并开放 MCP 写工具。写工具按 Action 的审批要求做写回。M0 只有编译器接口、OSI 导出接口，以及总是返回未实现的写工具。
